## Decisions

| Id | Decision | Why | Beat | Serves |
|---|---|---|---|---|
| SD1 | Python 3.14.8 | Team stack; every library has a 3.14 classifier; `uuid.uuid7()` is in the standard library for the public and event ids | 3.13: older with no benefit | LD1, DD3 |
| SD2 | FastAPI with synchronous endpoints, psycopg 3 synchronous pool (pool wait timeout 2 s, within NF3's budget; request concurrency per instance is set in AD4 and stays within the 40-thread default, one thread being held by the relay) | Request-scoped DB work, no event loop to debug for a 4-person team | Async stack: more moving parts with no throughput need at 20 writes/s | NF2, AD2 |
| SD3 | Plain SQL files loaded by the code, plain-SQL migration runner of our own (a few dozen lines) | Python convention for raw SQL; the schema is functions and an exclusion constraint written in SQL, so a migration tool would only add a dependency | SQLAlchemy/Alembic or a third-party SQL migrator: a dependency and its machinery for a handful of files | DD2, DD4 |
| SD4 | Pool of 5 connections per instance | Far under Cloud Run's 100-per-instance Cloud SQL limit; the instance-count side is AD4 / OI-20: max-instances 10 can overshoot to about 2 × 10 and a deploy overlaps revisions, so peak is about 20 instances × 5 = 100 connections, within 60 % of the database's 400 (pinned below) | Bigger pools: connection exhaustion | AD4 |
| SD5 | Integration tests run against a real Postgres 18.6 container started through the Docker CLI on port 55432 (override by env; host ports 55432–55499 are the run's environment constraint, OI-28) | Same major and minor as Cloud SQL today (Cloud SQL's minor follows its maintenance, so re-pin the test image when it moves); a fixed, known port | Testcontainers: another dependency for a one-container need | NF1, DD2 |
| SD6 | Pub/Sub wrapped behind our own publisher interface; fake in tests | Code conventions: wrap every external service | Using the client directly | I5 |
| SD7 | Config from environment variables, validated at boot | Fail at startup on misconfiguration | Config files | AD6 |
| SD8 | Container image built from the official Python slim image, installed from a hash-pinned lock file generated by pip-tools | Reproducible builds | Buildpacks: version of Python tied to platform's list | AD4 |
